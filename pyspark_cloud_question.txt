Aws glue :
AWS Glue is a serverless data integration service that simplifies Extract, Transform, and Load (ETL) pipelines.
Component of Glue:
Data Catalog: A centralized, persistent metadata repository that stores table definitions, schemas, and connection information.
Crawlers: Automatically scan data sources to infer schemas and populate the Catalog.
ETL jobs: AWS Glue can automatically generate PySpark scripts for these jobs, which run on a serverless Apache Spark environment.

 
Scenario based question 


Incremental Data Processing
You have a daily ETL job that processes 50GB of new data arriving in S3. How do you ensure the job only processes new files without re-scanning the entire bucket? 

Use Job Bookmarks. This feature allows AWS Glue to track the state of processed data by maintaining a state in the AWS Glue Data Catalog. 
You can also use S3 Partitions (e.g., /year=2024/month=05/day=13/) and pushdown predicates to filter data at the source level, which prevents Spark from loading unnecessary files into memory. 
 
Handling Data Skew & Performance
Scenario: Your Glue job is running extremely slow or failing with Out-Of-Memory (OOM) errors even though you've increased worker nodes. What do you investigate?
 
This often indicates Data Skew, where one partition is much larger than others, causing a single worker to do all the work.

Solution: 
Use Salting to redistribute data more evenly.
Optimization: Check if you are using DynamicFrames versus DataFrames. While DynamicFrames handle semi-structured data well, standard DataFrames are often better for complex Spark-level optimizations.
Scaling: Ensure Autoscaling is enabled so Glue can dynamically add or remove workers based on the actual workload.

Schema Evolution:
Scenario: A source database table has a new column added. How does AWS Glue handle this in the downstream Data Lake?
 
You should use AWS Glue Crawlers with a specific configuration for schema changes.
Configuration: Set the crawler to "Update the table definition in the Data Catalog" when a change is detected.
Validation: Use the AWS Glue Schema Registry to enforce or allow specific evolution rules (backward, forward, or full compatibility) to prevent breaking downstream queries in Amazon Athena
 
Choosing the Right Tool:
Scenario: You have a transformation involving heavy joins across multiple massive datasets that takes over 24 hours in Glue. Is Glue still the right choice?
 
Amazon EMR is excellent for serverless very complex, long-running Spark jobs with massive shuffles might be more cost-effective and performant then aws glue
 Use Glue for general ingestion and preparation, but consider moving heavy, multi-hour "big data" processing to dedicated EMR clusters where you have more granular control over Spark configurations 
 
Managing Sensitive Data
Scenario: Your source data contains PII (Personally Identifiable Information). How do you handle this within the Glue ETL pipeline?
 
Use the Sensitive Data Detection transform in AWS Glue. This allows you to automatically identify PII data like credit card numbers or SSNs. You can then choose to redact, mask, or encrypt these fields before they reach the target S3 bucket.
 
Scenario:  Your Glue Job fails with an OutOfMemory (OOM) error. How do you fix it? 
Identify Root Cause: Check CloudWatch metrics to see if the OOM is occurring on the driver node or the worker nodes
Driver OOM Fix: Avoid calling .collect() or .toPandas() which pulls distributed cluster data into a single node memory space.
Worker OOM Fix: Resolve data skew issues by salting join keys. Alternatively, scale up worker types from G.1X to G.2X for higher memory-per-core ratios
Reduce Partition Size: Adjust Spark max partition sizes to prevent loading single, massive chunks into memory. 

Scenario: How do you handle millions of small files in S3 causing slow Glue processing? 
Grouping Feature: Enable the groupFiles option within the S3 data source configuration ('groupFiles': 'inPartition').
Compaction Pipeline: Build a staging script that reads small objects and writes them back out as consolidated larger objects (~128MB to 512MB).
Athena/Iceberg: Implement modern storage frameworks like Apache Iceberg that handle metadata indexing independently of file counts.
 

Scenario: Your daily batch job processes 500 GB of JSON logs using an AWS Glue ETL job but takes too long to complete and frequently fails with Out-Of-Memory (OOM) errors.
Scale Up: Switch from standard Glue workers to G.1X or G.2X workers which provide more memory per Data Processing Unit (DPU).
Convert Format: Convert the source JSON data into an optimized, compressed columnar format like Parquet or ORC before processing.
Optimize Shuffling: Use Glue bookmarks to process only incremental data and enable dynamic frame partitioning to avoid large shuffle operations.
Use Spark UI: Enable the Spark UI on your Glue job to identify exactly which stage is causing the memory bottleneck.

AWS Lambda :
AWS Lambda is a serverless computing service that automatically manages infrastructure, allowing you to run code in response to triggers like HTTP requests, database updates, or file uploads. You simply upload your code, and AWS Lambda executes it when an event occurs, scaling resources as needed without manual provisioning. 

Scenario based question :

Scenario: A Lambda function triggers on an S3 file upload but crashes due to an out-of-memory error on a 10 GB file. How do you resolve it?
Do Not Load Entirely: Modify the function code to stop reading the file into memory all at once (avoid commands like .read() in Python).
Stream in Chunks: Implement S3 Select to query and retrieve only necessary rows, or use standard Python generators with the boto3 SDK to stream the payload line-by-line or block-by-block.
Scale Up the Compute: Swap the engine tool entirely by initiating an AWS Glue job via the Lambda trigger if heavy memory transformation is required

What are the hard limits of AWS Lambda and how to bypass it?
Timeout: Maximum execution time is 15 minutes.
Bypass: Split massive datasets into smaller chunks, or offload heavy processing to AWS Glue or AWS Batch.
Memory: Max allocation is 10 GB.
Bypass: Mount an Amazon EFS network file system directly to the function for unlimited temporary cache.
Payload Size: 6 MB for synchronous calls; 256 KB for asynchronous.
Deployment Package: 50 MB zipped, 250 MB unzipped. 
Bypass: Utilize Lambda Layers for heavy libraries (like Pandas or NumPy), or package functions into container images up to 10 GB.
 
How do you process a 100 GB file if Lambda has memory limits?
You should stream the file or process it in chunks using Python generators (yield) rather than loading the entire file into memory. 
Alternatively, use AWS Glue or Amazon EMR for heavy lifting.  
 
 How does Lambda handle scaling?
It scales horizontally(increase no of machine) by creating new instances of your function to handle concurrent requests.
 
How do you handle retries and failures?
Lambda processes events in either synchronous or asynchronous modes. 
In synchronous execution, failures return errors to the invoking service. 
In asynchronous mode, Lambda retries the event automatically up to two additional times(three attempts total).
Failed events can be sent to a Dead Letter Queue (DLQ) using Amazon SQS or Amazon SNS for later debugging.
 
What is an IAM Execution Role in aws lambda ?
It is the set of permissions granted to the Lambda function to access other AWS services (like S3 or CloudWatch) following the Principle of Least Privilege.
 
Explain the difference between Synchronous and Asynchronous invocations in Lambda?
Synchronous Invocation: The client service (e.g., Amazon API Gateway) calls the function and waits for a response. Errors must be caught immediately.

Asynchronous Invocation: The client service (e.g., Amazon S3 event) triggers Lambda and receives an immediate 202 success code. Lambda queues the event and automatically handles up to 2 built-in retries if it fails.
 
How do you secure data access permissions inside an AWS Lambda function?
IAM Execution Role: Every function must be bound to a unique, dedicated IAM role enforcing the Principle of Least Privilege.
Secrets Management: Fetch secure database passwords directly from AWS Secrets Manager at runtime rather than storing plain text environment variables.
No Access Keys: Never store static programmatic keys in code.
 
How do you handle errors and avoid data loss when Lambda consumes messages from an Amazon SQS queue?
Visibility Timeout: Set the SQS queue visibility timeout to at least 6 times the Lambda function timeout to avoid another worker picking up an unfinished message
Dead Letter Queues (DLQ): Configure an SQS DLQ or use Lambda Destinations on failure. This moves corrupt or un-parsable data records to a side queue for manual debugging after a preset number of retries.
Batch Item Failures: Return a specific payload (batchItemFailures) back to SQS, ensuring only the exact failed message stays in the queue while successful messages are cleanly deleted
