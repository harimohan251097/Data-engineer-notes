1. GROUP_CONCAT
Definition:
 The GROUP_CONCAT() function is an aggregate function in MySQL that concatenates values from multiple rows into a single string, separated by a specified delimiter. It helps combine column values into a single result.
Example:
SELECT GROUP_CONCAT(name SEPARATOR ',') FROM EMPLOYEE;

Input Table (EMPLOYEE):
name
-----
hari
mohan
meena

Output:
hari,mohan,meena


2. CONCAT() and CONCAT_WS()
Definition:
CONCAT() → Joins multiple strings or column values into one string (no separator).


CONCAT_WS(separator, …) → Joins values using a specified separator between them.


Examples:
SELECT CONCAT_WS("-", "SQL", "Tutorial", "is", "fun!");
-- Output: SQL-Tutorial-is-fun!

SELECT CONCAT('Ram','is','a','good','student') AS ExampleConcat;
-- Output: Ramisagoodstudent

SELECT CONCAT_WS(' ','Ram','is','a','good','student') AS ExampleConcatWS;
-- Output: Ram is a good student


3. TRUNCATE()
Definition:
 The TRUNCATE() function truncates (shortens) a number to the specified number of decimal places. Unlike rounding, it simply removes extra digits instead of adjusting the value.
Example:
SELECT TRUNCATE(135.375, 2);

Output:
135.37


4. JOIN (INNER, LEFT, RIGHT, FULL)
Definition:
 A JOIN is used to combine rows from two or more tables based on a related column. Different joins control which records are included in the result set.
INNER JOIN: Returns only rows with matching values in both tables.


LEFT JOIN: Returns all rows from the left table + matching rows from right.


RIGHT JOIN: Returns all rows from the right table + matching rows from left.


FULL JOIN: Combines results of LEFT and RIGHT joins (all rows).


Example (Simplified):
SELECT t1.id, t2.value
FROM T1
INNER JOIN T2 ON t1.id = t2.id;

Sample Tables:
T1: 1,2,3,4,null,null
T2: 5,6,2,4,null

Outputs:
INNER JOIN → 2,4


LEFT JOIN → 1,2,3,4,null,null (with nulls for unmatched right)


RIGHT JOIN → 5,6,2,4,null (with nulls for unmatched left)


FULL JOIN → union of all above (9 row) left join+right join - inner join

2	2
3	NULL
4	4
NULL	NULL
NULL	NULL

NULL	NULL



5. EXISTS
Definition:
 The EXISTS operator is used to test whether a subquery returns any rows. If the subquery returns at least one row, EXISTS evaluates to true.
Example:
SELECT SupplierName 
FROM Suppliers 
WHERE EXISTS (
  SELECT ProductName 
  FROM Products 
  WHERE Products.SupplierID = Suppliers.SupplierID 
    AND Price < 20
);

Output:
 Returns all supplier names who have at least one product priced below 20.

6. SELECT INTO
Definition:
 The SELECT INTO statement creates a new table and copies data from an existing table into it.
Example:
SELECT * 
INTO newtable
FROM oldtable
WHERE condition;

Output:
A new table newtable is created with the same structure and data as oldtable (filtered by condition).
7. UPDATE
Definition:
 The UPDATE statement is used to modify existing records in a table. You can update one or multiple columns at once, usually with a WHERE clause to limit rows.
Example:
UPDATE Employees 
SET salary = salary * 1.1 
WHERE department = 'HR';

Output:
All employees in the HR department will get a 10% salary increase.



8. DELETE
Definition:
 The DELETE statement removes one or more rows from a table. Use the WHERE clause to specify which rows to delete; otherwise, all rows will be deleted.
Example:
DELETE FROM Employees 
WHERE department = 'Finance';

Output:
All employees in the Finance department will be deleted.



9. LIMIT
Definition:
 The LIMIT clause restricts the number of rows returned by a query. It is useful for pagination or sampling data.
Examples:
SELECT * FROM Customers LIMIT 10;
-- Returns the first 10 rows

SELECT * FROM Customers 
LIMIT (SELECT COUNT(*)*50/100 FROM Customers);
-- Returns 50% of total rows


10. Wildcards with LIKE
Definition:
 Wildcards are special characters used with the LIKE operator in SQL to search for patterns in strings.
% → matches 0 or more characters


_ → matches exactly one character


[abc] → matches one character in list


[^abc] → matches one character not in list


[a-d] → matches characters in range


Examples:
SELECT * FROM Employees WHERE name LIKE '%hm%';  -- contains "hm"
SELECT * FROM Employees WHERE name LIKE 'h_m';   -- h + any + m
SELECT * FROM Employees WHERE name LIKE 'h[ot]m'; -- hom or htm


11. HAVING
Definition:
 The HAVING clause is used with aggregate functions to filter groups. Unlike WHERE, which filters rows, HAVING filters aggregated results after GROUP BY.
Example:
SELECT department, COUNT(*) AS total
FROM Employees
GROUP BY department
HAVING COUNT(*) > 5;

Output:
Returns only departments with more than 5 employees.



12. INSERT INTO … SELECT
Definition:
 This statement copies data from one table and inserts it into another. It is useful for duplicating data or migrating between tables.
Example:
INSERT INTO EmployeesBackup (id, name, salary)
SELECT id, name, salary 
FROM Employees
WHERE department = 'IT';

Output:
All IT department employees are copied into EmployeesBackup.


13. CASE
Definition:
 The CASE expression allows conditional logic in SQL. It works like an IF-THEN-ELSE statement and returns a value when the first matching condition is met.
Example:
SELECT name,
  CASE 
    WHEN salary > 50000 THEN 'High Salary'
    WHEN salary BETWEEN 30000 AND 50000 THEN 'Medium Salary'
    ELSE 'Low Salary'
  END AS salary_category
FROM Employees;

Output:
Each employee is classified into High, Medium, or Low salary categories.



14. COALESCE() and NVL()
Definition:
COALESCE(expr1, expr2, …) returns the first non-NULL value in the list.


NVL(expr, replacement) (Oracle only) replaces NULL with the given replacement value.


Example:
SELECT ProductName, 
       COALESCE(UnitsInStock, 0) + COALESCE(UnitsOnOrder, 0) AS TotalUnits
FROM Products;

Output:
Returns product name and total units, treating NULL values as 0.

19. Constraints
Definition:
 Constraints in SQL define rules for the data in a table. They ensure data integrity and prevent invalid data entry.
Common Constraints:
NOT NULL → Prevents NULL values


UNIQUE → Ensures all values in a column are unique


PRIMARY KEY → Combination of NOT NULL and UNIQUE, uniquely identifies each row


FOREIGN KEY → Ensures referential integrity by linking tables


CHECK → Ensures values satisfy a condition


DEFAULT → Sets a default value if none is provided


Example:
CREATE TABLE Students (
    StudentID INT PRIMARY KEY,
    Name VARCHAR(50) NOT NULL,
    Age INT CHECK (Age >= 18),
    DepartmentID INT,
    FOREIGN KEY (DepartmentID) REFERENCES Departments(DepartmentID)
);


20. SQL Injection
Definition:
 SQL Injection is a security vulnerability that allows attackers to interfere with SQL queries by injecting malicious input. It can lead to unauthorized access, data leaks, or data loss.
Example of Injection-Prone Query:
SELECT * FROM Users 
WHERE username = ' " + userInput + " ' 
AND password = ' " + passInput + " ';

Malicious Input:
username = admin
password = ' OR '1'='1

Result:
Attack bypasses authentication and logs in as admin.


Prevention:
Use prepared statements or parameterized queries.

 Window (or analytic) functions perform calculations across a set of rows related to the current row, without collapsing rows like GROUP BY.

25. Transactions
Definition:
 A transaction is a sequence of SQL statements that are executed as a single unit of work. It ensures ACID properties (Atomicity, Consistency, Isolation, Durability).
Key Commands:
BEGIN / START TRANSACTION → Start a transaction


COMMIT → Save changes


ROLLBACK → Undo changes


Example:
START TRANSACTION;
UPDATE Accounts SET balance = balance - 500 WHERE id = 1;
UPDATE Accounts SET balance = balance + 500 WHERE id = 2;
COMMIT;

Output:
Money transferred safely between accounts.



26. Indexes
Definition:
 An index improves query performance by allowing faster lookups in a table, similar to a book’s index. However, indexes increase storage and slow down writes (INSERT/UPDATE).
instead of scanning every row, SQL can quickly locate the required data.
Example:
CREATE INDEX idx_name ON Employees(name);

Output:
Queries filtering by name become faster. 
 
Type of index:
Clustered Index	
Determines the physical order of data in the table.
A table can have only one clustered index because data can be stored in only one order.
In many databases, the Primary Key is implemented as a clustered index by default.
CREATE TABLE employee(
id INT PRIMARY KEY,
name VARCHAR(50)
);

Non-Clustered Index:
Stores index data separately from the actual table data.
Contains pointers to the actual rows.
A table can have multiple non-clustered indexes.
 CREATE  INDEX idx_email
ON employees(email);

Unique Index
Ensures duplicate values are not allowed.
Improves lookup performance while enforcing uniqueness.
 CREATE UNIQUE INDEX idx_city
ON employees(city);

Composite Index (Multi-column):
Created on multiple columns.
Useful when queries frequently filter on multiple columns together.
CREATE INDEX idx_name_city
ON employees(name, city);

B-Tree Index (Most Common):
Most databases use B-Tree indexes by default.

Bitmap Index:
Uses bitmaps for low-cardinality columns.
Best For Columns with few distinct values:
Gender
 
Hash Index:
Uses hash table internally.
Best For Equality searches:
WHERE id = 101

Full-Text Index:
Used for searching textual data efficiently.

30. Stored Procedures

31. Triggers
Definition:
 A trigger is a set of SQL statements that automatically executes in response to certain events (INSERT, UPDATE, DELETE) on a table.
Example:
CREATE TRIGGER BeforeInsertEmployee
BEFORE INSERT ON Employees
FOR EACH ROW
SET NEW.created_at = NOW();

Output:
Automatically sets created_at when a new employee is inserted.



32. CTE (Common Table Expression)
Definition:
 A CTE is a temporary named result set defined using WITH that can be referenced in the main query. It improves readability and handles recursive queries.
Example:
WITH HighSalary AS (
  SELECT name, salary 
  FROM Employees 
  WHERE salary > 60000
)
SELECT * FROM HighSalary;

Output:
Employees with salary > 60000.



33. Materialized Views
Definition:
 A materialized view is similar to a normal view but stores the result set physically. It can be refreshed to update data and is useful for performance in large datasets.
Example (PostgreSQL / Oracle):
CREATE MATERIALIZED VIEW HighSalary AS
SELECT name, salary 
FROM Employees
WHERE salary > 60000;

Output:
A stored copy of high salary employees, which can be refreshed for updates.

48. Row between for cumulative sum :
	Row between: Counts a literal number of rows before or after the current row, completely ignoring the values inside those rows.
SELECT column_name, 
AGGREGATE_FUNCTION(column_name) OVER ( [PARTITION BY ...] 
ORDER BY ... 
ROWS BETWEEN [lower_bound] AND [upper_bound] 
) FROM table_name;
Here lower_bound and upper_bound have =5 standard value:
UNBOUNDED PRECEDINGStarts from the very first row of the partition.
n PRECEDINGIncludes the \(n\) rows before the current row.
CURRENT ROWIncludes only the row currently being processed.
n FOLLOWINGIncludes the \(n\) rows after the current row.
UNBOUNDED FOLLOWINGEnds at the very last row of the partition. 
 
Calculating a Running Total- To sum values from the beginning of the dataset up to the current row:
-- Adds current row + all previous rows
SUM(salary) OVER ( ORDER BY employee_id 
    ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
) AS running_total 
Calculating a Moving Average (3-Row Window)- To find the average of the previous row, current row, and next row:
AVG(daily_sales) OVER ( ORDER BY sale_date ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING ) AS moving_avg 
 Calculating a "Total to End"- To sum all values from the current row to the end of the partition: 
SUM(revenue) OVER ( ORDER BY sale_date ROWS BETWEEN CURRENT ROW AND UNBOUNDED FOLLOWING ) AS future_revenue 
49. Range between:
SELECT sale_date, amount, SUM(amount) OVER( ORDER BY sale_date RANGE BETWEEN INTERVAL '6 days' PRECEDING AND CURRENT ROW ) AS rolling_7_day_total FROM sales; 
Range between:Looks at the value in your ORDER BY column (like dates or currency) and includes all rows that fall within a specific value range, regardless of how many rows that takes.
